# Codex：编程开发

Codex 是你的 AI 程序员，用于理解代码、定位问题、修改程序、编写测试和解释技术方案。它适合在已有项目中完成范围明确、可验证的开发工作。

## 适合使用 Codex 的场景

| 任务 | 应提供的信息 | 预期交付 |
| --- | --- | --- |
| 修复 Bug | 报错、复现步骤、预期 | 根因、最小修复和验证结果 |
| 新增功能 | 用户流程、验收标准 | 实现、必要测试和说明 |
| 阅读代码 | 模块或文件路径 | 架构说明、调用关系和风险 |
| 代码审查 | 改动范围或 diff | 问题清单与修改建议 |

## 推荐使用流程

1. **描述结果，而不是只说技术名词**：例如“登录失败时提示用户，不要返回 500”。
2. **给出证据**：包含错误日志、复现步骤、相关路径和预期行为。
3. **先分析后修改**：要求它说明影响文件、方案和验证方式。
4. **小步修改**：优先最小改动，避免顺便重构不相关代码。
5. **验证结果**：运行测试、静态检查或按复现步骤确认修复。

## 高质量请求示例

> 项目路径：`src/auth`。登录接口在密码错误时返回 500，预期为 401 和统一错误提示。请先定位原因并给出最小修改方案；确认后修改代码，补充回归测试，最后报告运行过的验证命令和结果。

## 你应要求 Codex 说明的内容

- 需求理解、假设与不确定点。
- 将修改哪些文件，以及为什么。
- 是否会改变接口、数据结构或兼容性。
- 测试是否通过；没有运行的检查要明确说明。

## 使用注意

- 不要把密钥、生产数据库密码或真实用户数据粘贴进对话。
- 对删除、部署、发布、推送和迁移等不可逆操作，应明确授权。
- AI 生成的代码仍需要人工审查，尤其是安全、支付、权限和数据处理逻辑。
