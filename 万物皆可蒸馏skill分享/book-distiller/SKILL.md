# 书籍蒸馏

把一本书还原成一套能解释、能检查、能应用的知识结构。不要把逐章缩写当作蒸馏。

本 Skill 借鉴女娲的核心方法：抓取作者如何思考，而不只是复述作者说了什么；保留证据、矛盾、反模式与诚实边界。

## 输出原则

- 先还原全书要解决的问题，再提炼观点。
- 区分原文事实、作者主张、案例、外部事实与本次推断。
- 每个核心模型至少给出两个书内证据位置；材料不足时降级为“单点观点”。
- 默认用自己的话概括，只保留必要短引文，避免大段复制原书。
- 不替作者消除矛盾；区分观点演化、适用场景差异和真正冲突。
- 最终必须落到“读者能怎么用”，但不把所有书强行改造成行动清单。

## 工作流

### 1. 审计输入

先确认：

1. 书名、作者、版本或译本。
2. 内容是全书、节选、笔记还是二手摘要。
3. 是否有目录、页码或稳定章节标题。
4. 用户目标：理解、应用、教学、写作研究，还是快速判断是否值得读。

把范围标为“完整正文”“基本完整但部分不可读”“节选”或“只有公开介绍”。只有前两类可以称为全书蒸馏。

能从文件中确认的不要追问。若只有节选，继续处理，但在开头明确“结论仅覆盖所给材料”。若用户只给书名且要求完整蒸馏，先获取合法可访问的原文或请用户提供文件；不能用书评拼成“全书蒸馏”。

### 2. 选择书类路由

读取 [book-routing.md](references/book-routing.md)，按主导类型选择提炼重点。混合类型可组合两个路由，但不要套用所有模板。

### 3. 三遍阅读

**第一遍：骨架**

- 找出全书的核心问题、目标读者和章节功能。
- 用“因为A，所以B，最终得到C”写出主论证链。
- 标出前言、结论、重复章节和可能的转折点。

**第二遍：证据**

- 为每个候选观点记录章节/页码、证据类型和反例。
- 区分作者亲历、案例故事、数据、引用研究与纯判断。
- 检查同一观点是否在不同章节或情境重复出现。

**第三遍：生成力**

- 判断观点能否解释书外的新问题。
- 判断它是否具有作者或本书的辨识度，而非人人同意的常识。
- 写出适用条件、失效条件和作者没有回答的问题。

候选观点满足“跨章节复现、能生成新判断、有辨识度”三项时，升级为核心模型；满足一至两项时保留为行动规则或单点观点；均不满足则删除。

### 4. 建立证据账本

遵循 [evidence-rules.md](references/evidence-rules.md)。内部至少维护：

| loc_id | 提炼结论 | 证据位置 | 证据类型 | 置信度 | 反例/限制 |
|---|---|---|---|---|---|

`loc_id` 使用稳定格式，例如 `C03-S02-P087`。没有定位信息时写“位置不可确认”，禁止制造页码。不同版本页码可能变化时优先给章节名，并注明所用版本。OCR文字未经原页核对不得放进引号。

### 5. 生成交付物

默认使用 [output-schema.md](references/output-schema.md) 的“标准蒸馏”。根据用户要求可切换：

- **快速判断**：适合决定要不要读。
- **标准蒸馏**：适合真正理解全书。
- **应用版**：把模型映射到用户的真实问题。
- **教学版**：生成课程结构、例子与检测题。

只输出用户需要的版本，不一次倾倒全部模板。

### 6. 自检

交付前检查：

- 是否读到了原始材料，而不是依赖书评？
- 是否说清全书问题与论证主线？
- 每个核心模型是否有至少两个书内位置？
- 是否区分作者观点和本次推断？
- 是否保留反例、局限和矛盾？
- 行动建议是否真的由书中模型推出？
- 删除书名后，框架是否仍有本书辨识度？

任何一项不满足，都要修正或明确降级。

## 与费曼检测法联动

用户要求“学会这本书”时，在标准蒸馏后追加一个最小学习包：

1. 一句核心问题。
2. 三个必须会解释的模型。
3. 一个能实际完成的任务。
4. 一个容易答错的反例。
5. 一条交给 `$feynman-check` 的启动提示。

不要在本 Skill 内模拟完整检测对话；把检测交给 `$feynman-check`。

## 诚实边界

- 书籍蒸馏不能替代阅读原文中的叙事体验、细节和语气。
- 节选、扫描缺页或OCR错误会限制结论质量。
- 作者引用的研究可能过时或被误用；涉及当前事实、医学、法律、金融或具体数据时应另行核验。
- 小说和文学作品允许多种解释，不把一种主题解读写成唯一答案。
- 不生成大段受版权保护的原文或可替代原书的逐页复刻。
