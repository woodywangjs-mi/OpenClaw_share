# 通用知识图谱 Skill 设计说明

## 1. 文档目的

将一批散落的课程、文章、网页或文档整理成可在 Obsidian 中检索、关联和持续维护的知识图谱。

本文是后续开发通用 Skill 的需求与执行规范，不是某一次项目的操作记录。Skill 实现时不得把“59份课件、8个主题、14个概念”等案例数字写死，应根据每批资料自动分析。

建议 Skill 名称：`build-obsidian-knowledge-graph`

## 2. 已验证案例

本流程已经在一批讲课资料中完成验证：

- 输入：59份 HTML 课件。
- 结构化结果：59篇 Markdown 课程笔记。
- 主题分类：8个课程主题。
- 概念提炼：14个核心概念。
- 关系建设：课程、主题、概念之间形成上千条内部链接。
- 原始资料：全部保留，并能从笔记返回对应 HTML。

该案例只用于证明流程可行，不作为其他知识库的固定目标。

## 3. Skill 适用场景

用户出现以下需求时触发：

- “把这些课件做成 Obsidian 知识库。”
- “把这个文件夹整理成知识图谱。”
- “把 HTML、PDF 或 Markdown 批量转换成笔记。”
- “给现有笔记建立双向链接和核心概念。”
- “整理资料并在 Obsidian 关系图谱中展示。”
- “检查知识库有没有孤立笔记、重复概念或失效链接。”

不适用于：

- 只需要转换单个文件格式的任务。
- 只需要普通摘要、不需要长期维护的任务。
- 需要数据库、向量检索服务或在线 RAG 系统的任务。

## 4. 输入

### 4.1 必需输入

- 一个或多个资料目录。
- Obsidian Vault 目录，或允许新建知识库目录的位置。

### 4.2 支持格式

第一版优先支持：

- `.html`
- `.md`
- `.txt`

后续按需增加：

- `.pdf`
- `.docx`
- `.pptx`
- `.epub`

### 4.3 可选输入

- 用户指定的分类体系。
- 用户指定的核心概念。
- 是否复制原始资料。
- 是否修改现有 Obsidian 图谱配置。
- 是否需要学习路径、课程地图或内容创作索引。

## 5. 输出结构

默认生成以下结构，实际主题数量由资料决定：

```text
知识库根目录/
├── 00-知识库首页.md
├── 01-{主题一}/
│   ├── README.md
│   └── {结构化笔记}.md
├── 02-{主题二}/
│   ├── README.md
│   └── {结构化笔记}.md
├── 09-核心概念/
│   ├── README.md
│   └── {概念节点}.md
├── 90-原始资料/
│   ├── README.md
│   └── {原始文件复制件}
├── SOURCE_OF_TRUTH.md
├── AGENTS.md
└── CLAUDE.md
```

目录编号只用于保持稳定排序。主题多于8个时顺延编号；主题较少时不创建空目录。

## 6. 核心工作流

### 阶段一：资料审计

#### 目标

确定资料范围、格式、数量、重复关系和输出位置。

#### 操作

1. 只读扫描用户指定目录。
2. 排除缓存、构建产物、依赖、临时文件、密钥和明确的历史备份。
3. 统计文件格式、数量、标题和更新时间。
4. 检查同名文件、相似版本和重复内容。
5. 确认 Obsidian Vault 和知识库根目录。
6. 写入前说明：修改哪些路径、保留什么、是否移动原文件、是否修改 Obsidian 设置。

#### 禁止事项

- 不根据文件名臆测正文内容。
- 不移动、覆盖或删除原始资料。
- 不在未确认时把某个文件指定为最新版。

### 阶段二：转换为 Markdown 笔记

#### 目标

让每份资料变成可检索、可复习、可追溯的结构化笔记。

#### 每篇笔记至少包含

```markdown
---
title: 资料标题
type: 课程笔记
category: 所属主题
source_file: 原始文件绝对路径
tags:
  - 知识库名称
  - 资料类型
---

# 资料标题

## 内容摘要

## 知识结构

## 核心要点

## 学习与应用

## 知识图谱关系

### 核心概念

### 相关资料

## 来源说明
```

#### 转换规则

1. HTML 优先读取标题、正文标题、段落、列表和表格，忽略脚本、样式、导航和按钮。
2. 摘要必须来自原文，不根据常识补造内容。
3. 保留章节层级，不把所有内容压缩成一段摘要。
4. 原文件包含代码、参数、限制或操作步骤时，保留关键细节。
5. 产品版本、价格、跑分、新闻和政策等动态信息标注时效风险。
6. 每篇笔记必须能返回对应原始文件。

### 阶段三：自动主题分类

#### 目标

根据资料内容形成少量、清晰、互不重叠的主题入口。

#### 分类方法

1. 综合标题、一级标题、摘要和高频实体，不只看文件名。
2. 先形成候选主题，再合并同义或范围重叠的主题。
3. 每个主题都必须有明确的正向定义和边界。
4. 每份资料确定一个主要主题；需要跨主题表达时使用概念链接，不复制文件。
5. 默认主题数量根据资料规模决定：
   - 10份以内：2～4个主题。
   - 11～50份：4～8个主题。
   - 51～150份：6～12个主题。
   - 150份以上：先建立一级主题，再按需增加二级索引。

#### 主题 README

每个主题的 `README.md` 至少包含：

- 主题定义。
- 当前资料数量。
- 课程或资料目录。
- 推荐阅读顺序。
- 返回知识库首页的入口。

### 阶段四：提炼核心概念

#### 目标

建立跨主题连接，让图谱能够围绕知识而不是文件夹展开。

#### 概念选择标准

一个概念应满足至少两项：

- 出现在多份资料中。
- 对理解多个主题有帮助。
- 能连接基础知识和应用场景。
- 用户以后可能直接搜索或提问。
- 能形成明确、稳定、可解释的定义。

#### 概念合并规则

- 合并同义词、缩写和中英文别名，例如“检索增强生成”和“RAG”。
- 不把产品版本号、文件名或一次性活动名称当作核心概念。
- 概念边界不清晰时暂不创建，避免制造噪声节点。
- 概念数量不是越多越好，以图谱可读性为准。

#### 概念节点结构

```markdown
---
type: 核心概念
aliases:
  - 中英文别名
tags:
  - 核心概念
---

# 概念名称

## 一句话定义

## 相关概念

## 关联资料

## 应用场景

## 返回入口
```

### 阶段五：建立双向链接

#### 目标

形成“首页—主题—资料—概念—相关资料”的知识网络。

#### 必需连接

每篇资料笔记至少链接：

- 1个所属主题。
- 1～4个核心概念。
- 1～3篇高度相关资料。
- 1个原始文件入口。
- 1个知识库首页入口。

每个概念节点至少链接：

- 2篇关联资料；不足2篇时不应升级为核心概念。
- 1～3个相关概念。
- 核心概念地图和知识库首页。

#### 相关度判断

按以下优先级建立关系：

1. 同一问题的基础、进阶或实战关系。
2. 同一工具链的上下游关系。
3. 同一概念的不同实现、比较或案例。
4. 同一主题但解决不同问题的弱关系。

不得仅因为两篇文章都出现“AI”“工具”“模型”等泛词就建立关系。

### 阶段六：生成入口与学习路径

#### 知识库首页

首页至少包含：

- 知识库定位。
- 资料总数、主题数和核心概念数。
- 主题入口。
- 核心概念地图入口。
- 推荐学习路径。
- 原始资料索引。
- 维护入口。

#### 学习路径

学习路径应基于内容依赖关系生成，而不是简单按照文件名排序：

```text
基础概念 → 方法原理 → 工具使用 → 综合工作流 → 真实应用
```

### 阶段七：配置 Obsidian 图谱

此阶段仅在用户明确授权修改 Obsidian 设置时执行。

建议配置：

- 只显示当前知识库目录。
- 隐藏原始资料、备份和孤立文件。
- 核心概念使用醒目颜色。
- 不同主题使用不同颜色组。
- 适度提高节点和连线大小。
- 调整排斥力与链接距离，避免节点完全重叠。

修改前备份 `.obsidian/graph.json`，修改后在 Obsidian 中实际打开图谱确认。

## 7. 知识库导航

生成 `SOURCE_OF_TRUTH.md`，用于告诉用户和 Agent：

- 去哪里查找某类资料。
- 哪些目录负责存放什么。
- 原始文件与结构化笔记谁是内容依据。
- 多版本资料如何判断当前有效版本。
- 新资料应该如何收录。

默认规则：

1. 内容事实以原始资料为依据，Markdown 笔记用于检索和学习。
2. 原始资料更新后，重新生成或精确更新对应笔记。
3. 无法确认版本关系时保留冲突，不擅自指定最新版。
4. 日常新增文件不逐条写入顶层导航，由主题 README 承接明细。

## 8. 验证标准

### 数量一致性

- 笔记数量与纳入处理的原始资料数量一致。
- 每篇笔记都有唯一原始资料入口。
- 每个主题索引列出的资料真实存在。

### 链接完整性

- 检查所有 `[[双向链接]]`。
- 悬空链接数量必须为0；刻意保留的待创建概念除外，并须单独报告。
- 不出现多个无法区分的同名笔记。

### 内容完整性

- 每篇笔记包含摘要、结构、要点、关系和来源。
- 关键代码、参数、限制和操作步骤没有因摘要而丢失。
- 不将推测写成原文事实。

### 图谱质量

- 不出现大量孤立笔记。
- 不出现所有资料都连接到同一个泛化概念的“超级节点”。
- 每个核心概念都能解释为什么存在。
- 主题之间存在真实的跨域连接，而不是为了图谱好看强行连线。

### 安全与可恢复性

- 原始文件未被移动、覆盖或删除。
- 批量修改前有可恢复备份。
- Obsidian 配置修改前有单独备份。

## 9. 建议的 Skill 文件结构

```text
build-obsidian-knowledge-graph/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   ├── audit_sources.py
│   ├── convert_to_markdown.py
│   ├── build_links.py
│   └── validate_knowledge_base.py
└── references/
    ├── note-schema.md
    ├── classification-rules.md
    └── obsidian-graph-config.md
```

### 脚本职责

- `audit_sources.py`：统计资料、标题、格式、重复关系和排除目录。
- `convert_to_markdown.py`：把支持的资料格式转换为统一笔记结构。
- `build_links.py`：根据主题、概念和相关度生成双向链接。
- `validate_knowledge_base.py`：检查数量、路径、链接、孤立节点和配置文件。

脚本负责确定性工作；主题命名、概念边界和相关关系由 Agent 根据内容判断，避免把语义判断全部交给关键词计数。

## 10. 建议的 Skill 触发描述

```yaml
---
name: build-obsidian-knowledge-graph
description: 将本地 HTML、Markdown、文本及后续支持的 PDF、DOCX、PPTX 等资料整理成可在 Obsidian 中使用的知识库和关系图谱。用于批量生成结构化笔记、自动主题分类、提炼核心概念、建立双向链接、生成知识库首页与导航、检查悬空链接和孤立节点，以及在用户授权后配置 Obsidian 关系图谱。用户说“把这些课件做成知识库”“整理成 Obsidian”“建立知识图谱”“给笔记加双向链接”“检查知识库关系”时使用。
---
```

## 11. 推荐交互流程

### 第一次使用

1. 确认资料目录。
2. 确认 Obsidian Vault 或输出目录。
3. 只读审计并报告数量、格式和冲突。
4. 给出写入预览。
5. 用户确认后批量生成。
6. 完成验证并打开知识库首页。
7. 用户授权后再配置和打开关系图谱。

### 后续新增资料

1. 只读取新资料和知识库导航。
2. 判断目标主题和相关概念。
3. 生成对应笔记并更新主题索引。
4. 只有主题、概念或版本关系发生变化时才更新顶层导航。
5. 重新运行链接与孤立节点检查。

## 12. 最小成功标准

一次完整执行必须满足：

- 原始资料全部保留。
- 每份纳入资料都有结构化 Markdown 笔记。
- 知识库具有清晰主题，而不是一个平铺文件夹。
- 资料通过核心概念和相关资料形成真实连接。
- 首页、主题索引、概念地图和原始资料能够相互到达。
- 所有内部路径通过检查。
- 用户能够在 Obsidian 中打开首页并查看关系图谱。

## 13. 下一步

根据本文创建正式 Skill 时，应按以下顺序执行：

1. 使用 Skill 初始化工具创建 `build-obsidian-knowledge-graph`。
2. 编写精简的 `SKILL.md`，将详细格式与规则放入 `references/`。
3. 实现并测试四个确定性脚本。
4. 使用小型、中型和包含重复版本的三组资料进行验证。
5. 检查生成结果是否存在过度分类、泛词连线和版本误判。
6. 验证通过后再安装到 Codex Skill 目录。
